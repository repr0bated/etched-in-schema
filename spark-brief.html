The project in one paragraph

A self-contained 3tched identity — the “twin”, the living embodiment of a 3tched subsidiary — turns a business goal into deployed, verified infrastructure. It acts only through its own typed filesystem (3tchedFS), every action is authorised against its capabilities and leaves a tamper-evident receipt, and a Web3 index anchored on-chain lets anyone verify who did what, under what authority, without trusting the agent or operator. That link between on-chain artifacts and accountable, authorised actors is the gap blocking Web3 adoption.

Proven today

  • Identity container: 3tchedCtlChatbot (Incus, pool 3tched, profile 3tched-lungs), identity session <subsidiary-session>, service principal, persist volume, kept running by runit chatbot-identity.
  • First-person operation call: inside the container, write the plain JSON arguments to /run/mount/3tchedfs/operations/<plugin>/<method>/call (open read-write, write, fsync, read back on the same handle). Example identity_sled/get_own_identity with {} returned the identity, operation 51c8f91c-c2f1-4688-a985-fb41684adfff, chain events 10389/10390, outcome completed. The bridge identifies the caller from the kernel peer over the lungs Unix socket, checks the exact capability, commits via MutationEngine.
  • Infrastructure operations available to the identity: incus/* (create/start/stop/snapshot/devices), ovsdb_bridge/* (bridges, ports, transact), plus ~70 plugins. Each call is checked against the identity’s grants.
  • No network path to 3tched: the twin talks to 3tched only through its FUSE mount. Its only network will be the internet (Meta API, blockchain).
  • Chat path: UI (http://<door-ip>:8080) → door <door-ip>:8090 → chat_router.Chat → zeroclaw router on 127.0.0.1:8084 (protocol zeroclaw.v1) → model. Every turn receipted.
  • Avatar: IdentityAvatar.svelte speaks a fixed intro script (exact wording, no model) and answers spoken or typed questions via the chat path.

Rules that must not be broken

  • The plugin IS the schema. Backend schemas live only in Rust plugins under crates/op-plugins/src/state_plugins/, sealed into blobs. No standalone schema files in op-dbus (that is why drafts live in this repo).
  • UI is Svelte/SvelteKit + Vite + json-render’s Svelte renderer only. Every visible element is a catalog component.
  • Never edit Cozo directly, never bypass a permission denial, never add or remove Btrfs members outside explicit identity provisioning.
  • Deployment is ./activate-golden.sh / op-release-launch release (btrfs send/receive slots). Never hand-copy binaries onto the host as a deploy.
  • One Cargo process at a time; release builds need CXXFLAGS="-include cstdint".
  • Tests only when the owner asks.
  • Commit and push at the end of every working turn (owner policy, 2026-10-28): public repo github.com/repr0bated/etched-in-schema, branch master. No turn ends with unpushed work.

CMS: compliant by construction (owner direction, 2026-10-28)

The CMS is the showcase because it comes out usable and evidently controlled. Pick a handful of controls whose effect is visible on stage; each control → a CMS behaviour → evidence (receipt or anchor):

Control areaVisible behaviourEvidence
PII handling (NIST 800-53 PT)automatic redaction on publish; original kept only in the owner’s private scoperedaction operation receipt naming the triggering policy
Audit (AU)every create/edit/publish attributablereceipt chain: who, capability, when
Access control (AC)roles compiled into capability grantsa live denial showing the exact missing capability
Retention (SI-12)scheduled expiry/archivescheduled operation receipt
Integritypublished versions hash-anchoredon-chain anchor a judge can check

Pitch wording: “implements and evidences these controls” — never “compliant” or “certified” (an assessor declares compliance).

Remote identities: established design (owner, 2026-10-28)

WireGuard is only the establishment step: the peer key proves the identity once, the decoy issues the signed peer proof (OIA1) and the session gets its sealed credential (SID1). After that it is zero trust — every call carries the credential and the door’s interceptor re-verifies it, over any transport (internet, Cloudflare). 3tched-fs Credential mode is the remote form of the lungs. The mechanism exists; it needs testing and refinement, not a rebuild. Do not add a mesh (Netmaker/Cloudflare) as an identity layer.
